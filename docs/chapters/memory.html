CHAPTER 07 / 메모리

Load와 Store의 질서

메모리 주소가 늦게 밝혀져도 올바른 값을 읽는 방법.

약 8분 · Kunminghu V2 문서 기반 · 개념 학습

01같은 주소인지 나중에 알게 된다

레지스터 번호는 명령어를 읽으면 알 수 있지만 메모리 주소는 계산해야 알 수 있습니다. 앞선 store의 주소가 아직 준비되지 않았을 때, 뒤의 load가 같은 주소를 읽는지 즉시 판단하기 어려울 수 있습니다.

VISUAL WALKTHROUGH

캐시에 쓰기 전, Store에서 Load로

같은 주소의 앞선 Store가 아직 캐시에 반영되지 않았을 때를 관찰하세요.

Store QueueS0: [A] ← 42
주소 비교대기
뒤의 LoadL1: [A] 읽기 대기
D-cache[A] = 7

이 예제에서 주소 A의 캐시 값은 7입니다. 앞선 Store S0는 A에 42를 쓸 예정입니다.

기능 설명을 위한 순서도입니다. 단계 수는 실제 파이프라인 지연이나 회로 배선을 의미하지 않습니다.

02LSQ와 전달, 재실행

Load/Store Queue는 진행 중인 메모리 작업을 추적합니다. 더 앞선 store가 쓸 데이터를 적절한 조건에서 load로 전달하면 캐시 갱신을 기다리지 않아도 됩니다. 일찍 실행한 load가 순서를 위반한 것이 뒤늦게 확인되면 관련 작업을 재실행해야 합니다.

03커밋 이후에도 남는 쓰기 작업

프로그램 관점에서 store를 확정하는 것과 캐시·메모리 계층으로 쓰기를 처리하는 것은 구분됩니다. Store Buffer는 이 사이의 작업을 완충합니다. 용량, 병합, 캐시의 처리 능력 때문에 대기와 역압이 생길 수 있습니다.

기억할 한 가지

메모리 명령어의 의존성은 실제 주소와 실행 상태를 함께 확인해야 합니다.
