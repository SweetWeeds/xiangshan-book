설계에서 검증까지

Chisel, RTL, 시뮬레이션, DiffTest의 역할을 구분합니다.

약 8분 · Kunminghu V2 문서 기반 · 개념 학습

01Chisel로 하드웨어를 표현한다

XiangShan의 주요 설계는 Scala 기반 하드웨어 구성 언어인 Chisel로 작성됩니다. 소스와 구성을 elaboration하여 RTL을 생성합니다. 소프트웨어처럼 반복문이 있다고 해서 칩이 그 반복문을 순서대로 실행한다고 해석하면 안 됩니다. 생성되는 하드웨어 구조를 살펴봐야 합니다.

VISUAL WALKTHROUGH

검증 흐름에서 비교 지점 찾기

DUT와 참조 모델에 같은 프로그램을 주었을 때 무엇을 비교하는지 살펴보세요.

Chisel + Config소스 + 구성 고정
생성 RTL / DUT생성 전
참조 모델동일 ISA의 참조 모델
DiffTest 비교비교 전

먼저 소스 커밋과 Config를 선택합니다. Config가 바뀌면 생성 회로도 달라질 수 있습니다.

기능 설명을 위한 순서도입니다. 단계 수는 실제 파이프라인 지연이나 회로 배선을 의미하지 않습니다.

02참조 모델과 실행을 비교한다

DiffTest는 DUT와 참조 모델의 실행 결과를 비교해 기능 오류를 찾는 데 사용됩니다. 시뮬레이션에서 실행한 프로그램에 대해 차이를 포착할 수 있지만, 실행하지 않은 모든 경우까지 증명한 것은 아닙니다.

03무엇을 검증했는지 기록한다

성능을 비교하려면 같은 워크로드, 설정, 계측 구간을 사용해야 합니다. RTL 변경 전후의 등가성을 확인하는 formal equivalence와 프로그램을 돌려 보는 DiffTest는 서로 다른 근거를 제공합니다. 재현을 위해 소스 커밋, Config, 도구 버전, 실행 명령을 함께 남기세요.

기억할 한 가지

기능 검증, 성능 평가, RTL 등가성 검증은 질문과 근거가 서로 다릅니다.
