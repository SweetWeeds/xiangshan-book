문서를 읽기 전에 저장소의 브랜치를 확인하고 git rev-parse HEAD로 커밋을 기록하세요. 이 책은 Kunminghu V2 문서의 개념을 바탕으로 합니다. 다른 세대의 설명을 현재 체크아웃에 그대로 적용하지 말고 공식 문서의 버전 선택기를 확인하세요.

VISUAL WALKTHROUGH

소스 읽기: valid와 ready를 따라가기

일반적인 ready/valid 인터페이스 예제입니다. 두 신호가 동시에 1인 단계만 전송됩니다.

Producer데이터 없음
valid0 · 유효 항목 없음
ready1 · 받을 수 있음
Consumer전송 없음

valid = 0이면 전달할 유효한 항목이 없습니다. ready = 1이어도 전송은 없습니다.

기능 설명을 위한 순서도입니다. 단계 수는 실제 파이프라인 지연이나 회로 배선을 의미하지 않습니다.

02작은 질문으로 시작하기

처음부터 모든 파일을 읽기보다 “분기 예측 실패는 어디로 전달될까?”처럼 좁은 질문을 정하세요. 관련 모듈의 입출력, 상태 레지스터, valid/ready 조건을 따라가고 이해한 동작을 작은 예제로 확인합니다. 용량이나 폭은 이름만으로 추정하지 말고 Config와 파라미터를 확인하세요.

03다음 실험을 설계하기

예측 정확도, 캐시 미스, 실행 자원 대기 중 하나를 골라 원인을 설명하는 가설을 세워 보세요. 바꾸는 조건은 하나씩 제한하고 변경 전후의 기능을 먼저 확인하세요. 브라우저의 교육용 실험에서 나온 수치를 실제 코어의 성능 결과로 사용해서는 안 됩니다.
