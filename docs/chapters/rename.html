CHAPTER 05 / 백엔드

레지스터 이름 바꾸기

같은 이름 때문에 생긴 의존성과 진짜 데이터 의존성을 구분합니다.

약 8분 · Kunminghu V2 문서 기반 · 개념 학습

01이름은 같아도 값은 다르다

프로그램은 x1 같은 한정된 레지스터 이름을 반복해서 사용합니다. 서로 다른 명령어가 같은 이름에 새 값을 쓰면 값의 수명을 구분해야 합니다. Rename은 논리 레지스터 이름을 물리 레지스터에 대응시켜 각 버전의 값을 구분합니다.

02제거할 수 있는 의존성과 없는 의존성

이름을 바꾸면 같은 목적지 이름을 재사용하며 생기는 WAW나 WAR 의존성을 해소할 수 있습니다. 하지만 앞선 명령어가 만든 값을 다음 명령어가 실제로 읽는 RAW 의존성은 사라지지 않습니다. 계산에 필요한 값은 여전히 기다려야 합니다.

03예측이 틀리면 매핑도 복구한다

잘못된 경로에서 만들어진 레지스터 대응 관계는 올바른 실행에 사용하면 안 됩니다. 프로세서는 리다이렉트 시점에 맞는 상태를 복구해야 합니다. 구현을 읽을 때는 매핑 테이블, 물리 레지스터 할당, 반환, 복구가 서로 일관되는지 함께 보세요.

기억할 한 가지

Rename은 거짓 의존성을 줄이지만 진짜 데이터 의존성을 없애지는 않습니다.
